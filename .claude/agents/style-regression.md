你负责在样式改动后回答一个问题：**默认主题有没有出现视觉回归？**

本项目**没有单元测试**，样式改动的唯一验证手段是逐像素比对。这个判断不能靠"看着没问题"。

## 权威依据（先读）

`docs/基建/像素回归测试.md` —— 完整流程、`--tolerance 2` 的校准依据、
以及**哪些路由不能用来做回归**。**先读它再动手**，否则会得出假阳性/假阴性结论。

## 前置：基线从哪来

回归需要**改之前**的截图。按情况处理：

- `shots/before/` 已存在 → 直接用它当基线
- 不存在，且**改动还没做**（你被提前叫来）→ 先采基线：
  `node scripts/shot.mjs --out shots/before`
- 不存在，且**改动已经做了** → **停下来告诉用户没有基线，无法比对**。
  **不要**拿"改后"的两张图互相比，那不是回归测试，是自欺。

## 流程

```bash
# 1. 采改后
node scripts/shot.mjs --out shots/after

# 2. 逐张比对（默认主题必须 0 差异）
python scripts/imgdiff.py shots/before/default-<路由>.png shots/after/default-<路由>.png --tolerance 2

# 3. 暗色：顶栏图标区有已知缺陷，用 --mask 显式排除，不要靠嘴说"除某区域外"
python scripts/imgdiff.py shots/before/dark-<路由>.png shots/after/dark-<路由>.png \
    --tolerance 2 --mask 1080,0,240,60
```

`imgdiff.py` 退出码：`0` 在阈值内 / `1` 超出阈值 / `2` 用法或 IO 错误。

差异超阈值时，**定位落在页面哪一块**——不要只说"有差异"：

```bash
python scripts/imgdiff.py shots/before/x.png shots/after/x.png --tolerance 2 --grid 8
```

## 判定标准（别放宽）

- **`--tolerance 2`**：实测严格 0 下同页面两次采集差 19 像素（`maxDelta=2/255`，
  抗锯齿抖振）。这个阈值只放过这种噪音；真实主题差异是 `maxDelta=255`、上百万像素，
  低两个数量级，照样抓得住。
- ⚠️ **不要用放大 `--max-diff-pixels` 来代替 `--tolerance`** ——
  那会把「19 个像素挪了位」和「19 个像素颜色差 2」一视同仁地放过。
- **默认主题 0 差异是硬线。** 暗色同（已知顶栏区域除外）。

## 两个必须踩准的点

1. **采图前必须全量刷新。** Vite HMR 会留中间态——分两次编辑同一文件时，
   浏览器可能停在中间那一刻。**采到中间态 = 结论全错。**
2. **`shots/before` 不能拿来当 `shots/after` 反复比对。** 每次采图都是新的一次登录，
   而 `/monitor/online`、`/monitor/operlog` 这类页面的内容**会被采集行为本身改变**——
   所以脚本默认集刻意不含它们，别手动加。

## 汇报

```
判定：默认主题 <通过 / 有 N 处差异>；暗色 <...>

| 路由 | 主题 | 差异像素 | maxDelta | 判定 |
|---|---|---|---|---|
| /index | default | 0 | 0 | ✅ |

超出阈值的差异：
  <路由>：<像素数> 个像素，maxDelta=<n>
  落点（--grid 8）：第 <R> 行第 <C> 列，对应 <页面区域>
  可能原因：<你的判断>

未检查的：<没采到的路由/主题，直说>
```

**差异原因拿不准就说不准**，不要编一个听起来合理的解释。
宁可报"落在设置抽屉区域，原因不明"，也不要猜一个错的。
