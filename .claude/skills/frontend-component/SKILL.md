# 前端组件

## 一、⭐ 先找，再写

**绝大多数"我要写个组件"的需求，项目里已经有了。** 先跑：

```bash
ls frontend/src/components/
```

**这份清单是现读的，不是写死的** —— 任何人都可能加组件，写死的清单一定会过期，
而过期的清单会让 AI 写第二遍同样的东西。

### 业务模块最常打交道的几个（用途，这部分稳定）

| 组件 | 什么时候用 |
|---|---|
| `DictTag` | **列表列渲染字典值**。它接受任意 `{label,value}` 数组 —— 字典、写死选项、接口选项**三种来源共用它** |
| `Pagination` | 列表分页。生成器产出的页面已经用了 |
| `RightToolbar` | 列表右上角的刷新 / 列设置 / 搜索显隐 |
| `FileUpload` / `ImageUpload` | 附件 / 图片上传。**存储可切本地磁盘或 MinIO**，见 `docs/基建/文件存储.md` |
| `ImagePreview` | 图片预览 |
| `Editor` | 富文本 |
| `ExcelImportDialog` | Excel 导入 |
| `TableSelect` / `TreePanel` | 弹层选择表格 / 树 |
| `IconSelect` | 选图标 |
| `Crontab` | Quartz 定时任务表达式 |

> ⚠️ **组件级别的问题（某个 Element Plus 组件怎么用）不在这个 skill 里。**
> 项目已引入 39 个 Element Plus 组件 skill（`el-table` / `el-form` / `el-select` …），
> 直接问即可。这个 skill 只管**项目自己的封装层**。

## 二、Element Plus 组件用哪个 —— 看生成器那套约定

建表时字段的 `htmlType` 决定用哪个 Element Plus 组件，**那套映射已经定好了**
（17 个控件，见 `docs/生成器/字段类型.md`）。

**手写页面时照着同一套用**，别自创：
生成器产出的 `index.vue` 就是范例 —— **改已有页面前先看它怎么写的**。

## 三、什么时候该抽组件

| 抽 | 不抽 |
|---|---|
| 同样的结构**出现第三遍** | 只出现一次 —— 哪怕它很长 |
| 它会被**两个以上模块**用 | 只服务一个页面 |
| 你正在往里塞**第五个布尔参数** | 参数还在两三个以内 |

**"以后可能会用到"不是理由。** 抽错了的代价（多一层间接、参数越加越多）
比重复三行代码高得多。

**反过来的信号**：一个组件已经带了四个以上的 `v-if` 开关或 `props` 分支，
说明它其实是两个组件 —— 该拆了。

## 四、新建组件的落点与命名

```
frontend/src/components/<PascalCase>/index.vue
```

- **目录名 PascalCase**，与现有 21 个组件一致（`DictTag` / `FileUpload` / `RightToolbar` …）
- 组件内 `<script setup lang="ts">`
- **目录里放 `index.vue`**，这样 import 路径是 `@/components/Xxx`

### 自动导入

项目配了自动导入 —— **`src/components/` 下的组件不需要手动 import**，
模板里直接写 `<DictTag />` 就行。

> 别去手改自动生成的声明文件，改了会被覆盖 —— 它们是
> **`auto-imports.d.ts`**（在 `frontend/` 根下）与 **`src/types/components.d.ts`**。
> ⚠️ 这两个路径**别想当然**：一个不在 `src/` 下、一个在 `src/types/` 下
> （实测踩过：`eslint.config.js` / `.prettierignore` 里按"想当然"写的路径
> 全都指不到文件，排除静默失效）。要排除它们先 `find` 一下实际位置。

## 五、样式

**别写死颜色。** 项目有主题系统（多套主题预设 + 暗色模式），
颜色走令牌，见 `docs/基建/主题系统.md`。

> 那篇里记着一个 TinyColor 的坑 —— 踩了侧边栏悬停会变全黑。
> 动颜色相关样式前**先读它**，改完**跑像素回归**（交给 `style-regression` 代理）。

---

## 排查

- **想知道有没有现成的** → `ls frontend/src/components/`，别凭记忆
- **组件不生效 / 模板里没渲染** → 确认它在 `src/components/` 下（自动导入只扫这个目录）
- **改主题色后样式错乱** → `docs/基建/主题系统.md`，多半踩了 TinyColor 那个坑
- **生成的页面里组件用法看不懂** → 那就是范例本身，`docs/生成器/模板增强清单.md` 有解释
- **改了样式想确认没弄坏别的页** → 交给 `style-regression` 代理跑像素回归
