# AI 工程层版本体检

## 为什么需要它

模板仓库是主战场，**AI 工程层会持续改进**。而**实例是复制出去的**
（当前选择是直接复制，不是插件依赖 —— 取舍见 `AI工程化需求.txt` §4.3）。

既然是复制，就有个必然的问题：**模板改了，实例不会自动跟上 —— 而且看不见差别在哪。**
看不见就不会有人去同步，差距只增不减。

**这个 skill 让差别可见。它只报告，不合并。**

## 怎么用

```bash
node scripts/ai-layer-check.mjs --template <模板目录>            # 体检
node scripts/ai-layer-check.mjs --template <模板目录> --check     # 有"落后"则 exit 1（可挂 CI）
node scripts/ai-layer-check.mjs --template <模板目录> --verbose   # 连一致的也列出来
```

例：`node scripts/ai-layer-check.mjs --template ../code`

**AI 工程层的范围**：`CLAUDE.md` / `README.md` / `.gitlab-ci.yml` / `docs/` / `.claude/` / `scripts/`。

**排除掉的**（它们是**项目状态**不是模板资产，本来就该两边不同）：

- 棘轮基线（`*-baseline.json`）—— 存量错误每个项目不一样
- `docs/业务/` —— 生成物
- `.ai-layer/` 与 `.claude/settings.local.json` —— 项目历史与个人设置

> **凭据类占位符怎么处理的**：`.template-init.json` 里凭据是**打码的**（`***`），
> 拿不到真值。早先这会**误报**一批文件"有差异"（`CLAUDE.md` / `数据库.md` /
> `doc-scan.mjs` 都含 `DB_PASSWORD`），而它们恰恰最该跟进。
> 现在脚本会把**替换不掉的占位符当通配符**再比一次 ——
> 匹配得上说明差异只是那个凭据，文件其实没变。

## 四类结果怎么读

| 分类 | 含义 | 怎么办 |
|---|---|---|
| **❌ 模板有、这里没有** | **未同步的改进** —— 最要紧的一类 | 看一眼内容，值得要就带过来 |
| **✅ 可安全带过来** | 两边不同，**但本地从没动过** | **可以放心用模板版覆盖** —— 不会丢东西 |
| **⚠ 要人判断** | 两边不同，**且本地动过** | **必须人看** —— 直接覆盖会丢掉本地改动 |
| **· 这里独有** | 本地新增的文档或脚本 | 通常不用管；如果是通用的，考虑反向合并回模板 |

### 怎么分辨"可安全带"和"要人判断"

靠 `init.mjs` 在实例化时记的那份基线（`.ai-layer-manifest.json`）：

```
实例当前哈希 == 基线哈希  →  这个文件实例从没动过  →  ✅ 可安全带
实例当前哈希 ≠ 基线哈希  →  本地动过              →  ⚠️ 要人判断
```

**没有这份基线**（老实例、或 clone 时没带上）时，脚本分不出来 ——
一律按「要人判断」处理，退化成保守行为。这份基线就是用来消掉这个不确定性的：
**没有共同祖先就分不出"模板改了"和"本地改了"，而实例里不一定有 git。**

> ⚠️ **即使标了「可安全带」，覆盖仍然是人的决定** —— 脚本只摆依据，不自动动手。
>
> ⚠️ **带过来时不要整目录拷贝**：模板文件里是**占位符**，直接拷会把实例的真实值
> （库名、端口、凭据）换成裸占位符。要么带着替换一起做，要么照下面的规矩手工改。

## 做合并时的规矩

1. **先看 diff，再决定** —— 别整目录覆盖
2. **优先带"约定"和"脚本"，谨慎带"文档"** —— 文档往往被本地改过（项目特有的坑写进去了）
3. **带完跑一遍门禁**：
   ```bash
   node scripts/skill-lint.mjs
   node scripts/element-plus-scan.mjs --check
   node scripts/init.mjs --check
   ```
4. **别把 `.template-init.json` 带过来** —— 那是实例自己的取值记录

## 排查

- **报告里几乎每个文件都"有差异"** → 大概率是**占位符没还原**：
  实例缺 `.template-init.json`，或模板里有新的占位符是它没有的
- **`--template` 报"看起来不是模板仓库"** → 路径指错了，模板仓的标志是 `scripts/init.config.mjs`
- **凭据类文件一直报差异** → 已知局限，忽略
- **想知道某个差异是哪边改的** → 没有 git 就查不了。看文件里的日期注释，或问人

## 汇报

```
对比：<实例> ←→ <模板>
❌ 落后 N 个：<列出来，逐条说值不值得带>
✅ 可安全带 M 个：<列出来 —— 本地没动过，覆盖安全>
⚠ 要人判断 K 个：<列出来，标明"疑似模板更新"还是"疑似本地改过"及依据>
· 本地独有 J 个：<列出>
建议：<先带哪几个；哪几个要人拍板>
没做的：<没带的、没验证的>
```

**别自作主张覆盖。** 报告是你的产出，"要不要带、带哪些"是人的决定 ——
除非用户明确说了"都带过来"。
