# 更新项目文档

`docs/` 是项目的知识主体，`CLAUDE.md` 只留索引和铁律。
**改完代码不更新文档，文档就开始过期** —— 而过期的文档比没有文档更糟，
因为它会被当真。

## 核心：路由表

先看这次改了什么，再决定更新哪里。**一次改动可能命中多行。**

| 改了什么 | 更新哪里 |
|---|---|
| **新增业务模块** | ① 跑 `node scripts/doc-scan.mjs` 生成骨架<br>② 在新建的 `docs/业务/<模块>.md` 里补 **一句话** + `业务规则` / `设计取舍` / `⚠️ 坑`<br>③ `docs/README.md` 的「业务」小节若需列举则同步 |
| **改了已有模块**的字段 / 菜单 / 权限串 | 跑 `node scripts/doc-scan.mjs`（表格自动刷新）→ **复核** `业务规则` 是否还成立 |
| **改了已有模块**的业务逻辑 | 只改 `docs/业务/<模块>.md` 的叙述三节，不用跑脚本 |
| 改了 `vm/vue/v3ts/*.vm` | `docs/生成器/模板增强清单.md` |
| 加了新 `htmlType` / 改了存储建议 | `docs/生成器/字段类型.md` |
| 加了新规则键 / 改了 `validation_rule` 结构 / 改了选项来源 | `docs/生成器/校验规则.md` |
| 动了 `is_common` 的机制或规划原则 | `docs/生成器/查询条件常用非常用.md` |
| 改了主题 token / `applyTheme` / 主题相关 SCSS | `docs/基建/主题系统.md` |
| 改了 `scripts/typecheck*` / 棘轮基线策略 | `docs/基建/类型检查棘轮.md` |
| 改了 `scripts/lint-ratchet.mjs` / `eslint.config.js` / lint 规则 | `docs/基建/前端代码规范.md` |
| 改了 `scripts/shot.mjs` / `imgdiff.py` / 回归流程 | `docs/基建/像素回归测试.md` |
| 改了端口 / `docker-compose.yml` / 启动步骤 | `docs/基建/环境与启动.md` |
| 改了 `sql/` 下的脚本 / 库结构 | `docs/基建/数据库.md` |
| 改了后端分层或权限约定 | `docs/基建/框架分层与权限约定.md` |
| 改了 `@@MAVEN_ARTIFACT_PREFIX@@-biz` 模块的接线（pom） | `@@MAVEN_ARTIFACT_PREFIX@@-biz/README.md` |
| **新建 / 改动了 `.claude/skills/` 下的 skill** | ① 跑 `node scripts/skill-lint.mjs`（硬约束违反会让 skill 装不上）<br>② 若新增了 skill，同步 `CLAUDE.md` 的仓库结构 |
| **改动了 `.claude/commands/`** | 同上（命令的 frontmatter 写错会静默不出现） |
| **改名 / 删除了任何文件** | 跑 `node scripts/ref-check.mjs --check` —— 全仓 `.md` / `.txt` 里引用它的地方要一起改。**没有任何东西会自动提醒你** |
| **一轮较长的改动收尾** | 跑 `/ai-changelog` 记一条（改了什么 / 为什么 / **哪些没验证**） |
| **前端用到了新的 Element Plus 组件** | 跑 `node scripts/element-plus-scan.mjs --check`；报缺失则跑 `--fetch` 拉技能（见 `docs/基建/技能规范.md`） |
| **新踩到一个坑** | 就近写进对应文档的 `## ⚠️ 坑` |
| **做了一个有取舍的决定** | 就近写进对应文档的 `## 设计取舍` |

### 「就近」怎么判断

**改了它会不会只影响一个业务模块？**

- 会 → `docs/业务/<模块>.md`
- 不会、且只跟生成器有关 → `docs/生成器/`
- 其余 → `docs/基建/`

**不要新开第 4 个分类** —— 先试着塞进现有三类，确实塞不进再说。
（刻意没有「决策」和「已知坑」两个目录：决策离开它所属的机制就没人读，
坑也是这样。所以它们就近住进对应文档的 `## 设计取舍` / `## ⚠️ 坑`。）

## 写叙述三节的标准

`docs/业务/<模块>.md` 的表格部分是**脚本生成的，别手改**（下次跑脚本会覆盖）。
叙述三节是脚本永远不碰的，由你维护 —— **这三节才是文档的价值所在**：

| 小节 | 写什么 | 不写什么 |
|---|---|---|
| `业务规则` | 字段联动、状态流转、隐含约束、谁有权改什么 | **能从上面表格读到的不要重复** |
| `设计取舍` | 这个模块里非显然的选择，以及**为什么** | 显而易见的实现细节 |
| `⚠️ 坑` | 这个模块**特有**的坑 | 通用坑（生成器/主题/构建）→ 写进 `docs/生成器/` 或 `docs/基建/` |

> ⚠️ **读代码看不出来的才值得写。** 如果一条规则 grep 一下就知道，写进文档
> 只是增加噪音和过期风险。
>
> 若确实没什么特别的，`设计取舍` 里写一句**「无，标准生成产物」** ——
> **明确说「没有」比留空有用**，读的人才知道不是忘了写。

## 三条硬约束

破了这套体系就退化成一个「大文档 + 索引」，即回到起点。

1. **单份文档超过 400 行必须拆** —— 分层存在的意义就是单份别太大。
   拆的时候先问：拆出来的部分属于哪个分类？
2. **`docs/README.md` 每行必须带「什么时候读」** —— 只写标题等于没写。
   索引的价值在于让读的人**判断要不要读**，不光是知道有什么。
3. **不新开第 4 个分类** —— 见上。

## 收尾自检

改完代码、提交之前，跑这几条：

```bash
node scripts/typecheck.mjs          # 类型检查棘轮：只报【新增】错误，有新增则 exit 1
node scripts/lint-ratchet.mjs       # ESLint 棘轮：同上，管代码问题与 Vue/TS 规则
node scripts/doc-scan.mjs --check   # 文档与代码/数据库是否一致，有漂移则 exit 1
```

> 两条都是**为 CI 设计的**（有漂移则 exit 1），但**项目目前没接 CI**，
> 所以这两步得手动跑 —— 别跳过，它们是这套体系唯一的自动保护。

`doc-scan --check` 在模板仓库本身里跑要带连接参数（占位符还没实例化）：
`--container <容器> --password <密码> --db <库名>`。

- 报「生成块过期」→ 跑一次 `node scripts/doc-scan.mjs` 刷新
- 报「缺文档」→ 那个模块还没建文档，见上面的路由表

## 别做的事

- **别手改 `<!-- BEGIN GENERATED -->` 块里的内容** —— 会被脚本覆盖。
  发现里面内容是错的，那是**数据库配置错了**，去修数据，不是改文档。
- **别把 CLAUDE.md 撑回去** —— 它是每次会话自动加载的，正文一律进 `docs/`。
  CLAUDE.md 只该增长「铁律」那一段（如果确实有高频到必须默认可见的事）。
- **别为了写而写** —— 这次改动如果没带来新知识（重构、改名、修 bug），
  跑一下 `--check` 确认没漂移就够了，不需要硬凑一段叙述。
