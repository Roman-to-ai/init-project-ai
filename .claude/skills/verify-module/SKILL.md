# 验证业务模块

**"点一遍"不算验证** —— 那不可复现，也说不清到底点了什么。
这个 skill 把验证变成**有清单、有证据、有明确结论**的过程。

## 〇、前提：服务得在跑

```bash
netstat -ano | grep LISTENING | grep -E ':<前端端口>\s|:<后端端口>\s'
```

起不来的话**先跑 `/start-project`**，别在这里排查启动问题。

> ⚠️ **确认你连的是本项目。** 开发机上常有别的项目占着 8080 —— 那是**别的应用**，
> 症状是所有路径都 404。先 `curl` 一下后端接口确认身份。

## 一、拿到登录态

驱动浏览器需要一个已登录的 token。**三条路，按顺序试**：

**a) 走界面手工登录**（最直接）

用 Playwright MCP 打开登录页，填 `admin` / `admin123`。
**如果开了验证码**，这条路需要人眼看一下图 —— 那走 b 或 c。

**b) 从 Redis 读验证码答案**（脚本化的办法）

框架把答案写在 `captcha_codes:<uuid>`，**只读**：

```bash
# 先 GET /captchaImage 拿 uuid，再：
docker exec -i <PROJECT_SLUG>-redis redis-cli -n 0 get captcha_codes:<uuid>
```

有效期短，拿到就立刻用。（`scripts/shot.mjs` 里就是这么干的，见它的 `captchaFromRedis`。）

**c) 直接拿 token**（最省事）

用 `scripts/shot.mjs` 的登录逻辑拿 token，或在浏览器里手工登录后
F12 复制 cookie 里的 `Admin-Token`。

**token 怎么给浏览器用**：设成 cookie —— 名字 `Admin-Token`，
domain 是前端主机名，path `/`。设置后再导航，否则第一帧还是未登录页。

## 二、逐项验（**这是清单，别跳**）

| # | 验什么 | 怎么算通过 |
|---|---|---|
| 1 | **菜单可见** | 登录后侧边栏有该模块的菜单项。**改过菜单没重新登录会看不到** —— 菜单和权限缓存在 Redis |
| 2 | **列表出数据** | 打开列表页，表格渲染、分页条在、**有真实数据行**（不是空表） |
| 3 | **查询条件** | 常用的那几个默认显示、占满一行；次要的收在「展开」里 |
| 4 | **新增** | 点新增 → 表单弹出 → 填**必填项** → 保存 → **列表里出现这条** |
| 5 | **修改** | 点编辑 → 表单带出原值 → 改一个字段 → 保存 → **列表里值变了** |
| 6 | **删除** | 点删除 → 确认 → **列表里没了** |
| 7 | **权限按钮** | 该有的按钮在（`新增`/`修改`/`删除`/`导出`）。**一个都不显示**多半是权限串对不上 |
| 8 | **无报错** | 控制台没有 error；网络面板没有 4xx / 5xx |

**第 4–6 项要真改数据** —— 用**测试数据**，别拿正式数据练手。
删除类操作先确认你在开发环境。

> 验证完记得把造出来的测试数据清掉，或明确记进「遗留」。

## 三、别只看"看起来没问题"

**最常见的假通过**：页面渲染出来了，但数据是空的 / 接口悄悄 4xx 了。
所以第 2、8 项要**真的去看**：表格里有行吗？网络面板干净吗？

**权限相关**：按钮"不显示"和按钮"点了 403"是两种不同的病 ——
前者是 `sys_menu.perms` 没配，后者是 `@PreAuthorize` 与 `perms` 不一致。
见 `docs/基建/框架分层与权限约定.md`。

## 四、留下证据（可选但推荐）

改过样式的模块，顺手跑一次截图留证：

```bash
node scripts/shot.mjs --out shots/<模块名> --routes <该模块的路由>
```

纯功能验证不强制 —— 截图是给**样式回归**用的，见 `docs/基建/像素回归测试.md`。

## 排查

- **登录页要验证码** → 走上面 b/c 两条路
- **所有接口 404** → 你连的是**别的应用**，确认后端端口
- **菜单看不到模块** → **重新登录**；再不行查 `sys_menu` 与 `@PreAuthorize` 是否一致
- **列表空但接口 200** → 看返回的 `rows` 是不是空数组；是的话是数据问题不是页面问题
- **控制台报 `Cannot read property of undefined`** → 多半是 `index-bak.ts` 没合并进 barrel，类型没导出

## 汇报

**用这个结构，不要贴代码**：

```
模块：<功能名>（<表名>）　路由：<路由>
数据：<用的什么测试数据，几条>
结果：
  菜单可见   ✅
  列表出数   ✅（N 行）
  查询条件   ✅ 常用 3 个占一行
  新增       ✅
  修改       ✅
  删除       ✅
  权限按钮   ✅ 4 个
  无报错     ✅ 控制台 0 error，网络 0 个 4xx/5xx
没验的：<哪一项没跑、为什么 —— 这栏必须有内容或写"无">
遗留：<测试数据是否清理、发现的小问题>
```

**没做的事就不要写成做了。** 哪一项没验就明说哪一项，
**"没验"比"验了但其实是假通过"好得多**。

> 目前是**人工驱动 + MCP 辅助**的方式，还没有可进 CI 的自动化脚本。
> 要自动化得先解决"服务怎么在 CI 里起"和"测试数据怎么造"两件事。
