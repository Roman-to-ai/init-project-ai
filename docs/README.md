## 症状 → 文档

排查问题时按**现象**找，比按类型翻快：

| 现象 | 去哪儿 |
|---|---|
| 菜单不显示 / 新菜单看不到 | [`业务/README.md`](业务/README.md) 的「重建顺序」——**要重新登录**，菜单和权限缓存在 Redis |
| 按钮点了 403 / 按钮不显示 | [`基建/框架分层与权限约定.md`](基建/框架分层与权限约定.md)——`@PreAuthorize` 与 `sys_menu.perms` 对不上 |
| 某个筛选条件没生成出来 | [`生成器/模板增强清单.md`](生成器/模板增强清单.md)——`dictType` 为空或 `htmlType` 拼错会让整个 `el-form-item` 静默消失 |
| 树表生成的页面**表格空白** / 父节点下拉是空的 | [`生成器/模板增强清单.md`](生成器/模板增强清单.md) 的「合并丢过两处树表代码」——`getList()` 少了 `handleTree`、`handleUpdate()` 少了 `getTreeselect` |
| 生成的页面字段名是英文 | 建表时字段 `comment` 漏了，补注释后重导 |
| 改了模板但没生效 | 模板打在 jar 里——**必须 `mvn install` 再重启** |
| 改了后端代码但没生效 | 同上，直接重启 jar 不生效 |
| 类型检查报了一堆新错 | [`基建/类型检查棘轮.md`](基建/类型检查棘轮.md)——可能只是列顺序变了导致的假警报 |
| 样式改动后看着像有 bug | [`基建/像素回归测试.md`](基建/像素回归测试.md)——先**全量刷新**，Vite HMR 会留中间态 |
| 侧边栏悬停变全黑 | [`基建/主题系统.md`](基建/主题系统.md) 的 TinyColor 陷阱 |
| 端口连不上 / 连到了别的库 | [`基建/环境与启动.md`](基建/环境与启动.md)——确认用的是 3307/6380 而不是 3306/6379 |
| 上传的图/附件不显示、老图 404 | [`基建/文件存储.md`](基建/文件存储.md)——MinIO 模式下可能是对象不存在又没开本地回退 |
| 上传报 `NoSuchBucket` | [`基建/文件存储.md`](基建/文件存储.md)——看 `minio-init` 容器的退出码 |
| 前端 `pnpm dev` 停了但端口还占着 | [`基建/环境与启动.md`](基建/环境与启动.md)——Windows 上要单独杀子进程 |

## 维护这套文档

**改完代码后按 `.claude/skills/update-docs/SKILL.md` 的路由表更新对应文档。**
也可以直接喊 `/update-docs`。

三条约束（破了这套体系就退化成一个大文档）：

- **单份文档超过 400 行必须拆** —— 分层存在的意义就是单份别太大
- **本目录每行必须带「什么时候读」** —— 只写标题等于没写
- **不新开第 4 个分类** —— 先试着塞进现有三类，确实塞不进再说

体检（有漂移则 exit 1，也可以挂进 CI）：

```bash
node scripts/doc-scan.mjs --check
```
