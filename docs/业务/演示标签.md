## 业务规则

- 这是**多对多的被关联端**（样板）：产品 ←→ 标签的关联存在辅助表 `biz_demo_product_tag`，
  标签表本身是**普通单表**，不需要任何特殊配置。
- `tag_color` 不上列表、也不参与生成逻辑 —— 顺便说明「列可以有业务之外的含义」。
- **这张表开了「逻辑删除」**（`gen_table.options` 里 `softDelete=1`）：删标签只是把 `del_flag` 翻成 `'2'`，
  列表自动看不见它；恢复就是 `update biz_demo_tag set del_flag='0' where tag_id=…`。
  其它演示模块都是物理删除，正好形成对照。

## 设计取舍

- **建这张表就是为了给多对多一个样板**：只有两个业务列，其余是审计列。
  真正的看点在产品那侧 —— `biz_demo_product.tag_names` 的 `validation_rule` 里那套
  `junctionTable` 配置，见 `docs/生成器/表与关联.md` §4。
- 状态列（`status`）没配字典、也没上列表：`radio` 没字典会退化成普通输入框，
  与其留个四不像，不如先不上。
