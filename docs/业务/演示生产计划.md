## 业务规则

- **明细随主表一起提交**，Controller **没有额外端点**（仍是标准 6 个），
  明细通过主表 `@RequestBody` 里的 `bizDemoPlanItemList` 一起带上来。
- 新增：先插主表拿主键，再 `insertBizDemoPlanItem` 批量插明细。
- 删除：**先删子再删主**。
- 写方法都带 `@Transactional`。

## 设计取舍

### 修改是「全量替换」，不是按行 diff

`updateBizDemoPlan` 的语义是：

```java
bizDemoPlanMapper.deleteBizDemoPlanItemByPlanId(planId);  // 先全删
insertBizDemoPlanItem(bizDemoPlan);                       // 再全插
```

即明细行**没有独立的身份**，每次修改都是整批换掉。

这是生成器的默认产物，不是本模块的选择。它的实际含义是：
**两个人同时编辑同一张计划，后提交的会整批覆盖前者的明细**，
而不是「各自只改自己那一行」。

> 真实项目若明细有独立生命周期（如已开工/已领料的工单行），
> **必须改成按行 diff**，否则会丢数据。

### 子表没有独立菜单和权限串

`biz_demo_plan_item` 在 `gen_table` 里有记录，但 `sys_menu` 里**没有任何**对应菜单
（无 C 无 F）。这是主子表的**正常形态** —— 明细的权限完全由主表决定。

`scripts/doc-scan.mjs` 认得这种情况，会把它折叠进本篇而不是单独成篇。

## ⚠️ 坑

- **全量替换的并发含义**见上「设计取舍」，这是本模块最需要知道的一点。
- **子表字段的注释不能叫「序号」**：`seq_no` 的注释一度就是「序号」，
  结果与框架模板**自带的行号列**撞名，列表里出现两个「序号」。
  改成「行号」解决。
- 修这条时踩到了 `synchDb` 的坑 —— 详见 `docs/基建/数据库.md` 的「同步数据库」一节。
