# 主题系统

> 前端有多套可切换的**主题预设**（当前 10 套）。加一套主题 = 在
> `src/config/themes.ts` 里加一个对象，**不用动其他任何文件**。

## 架构：四个文件，各管一段

| 文件 | 职责 |
|---|---|
| `src/config/themes.ts` | **主题注册表**（类型定义 + 预设数据）。改配色只改这里 |
| `src/utils/theme.ts` | `applyTheme()` 主题引擎；`handleThemeStyle()` 负责主色派生 |
| `src/store/modules/settings.ts` | `themeId` / `customPrimary` / `sideTheme` 状态 + `refreshTheme()` |
| `src/layout/components/Settings/index.vue` | 设置面板里的主题色卡 |

## 主题预设的数据结构

预设对象顶层除了 `tokens`，还有三个**可选开关**（注意：写在对象顶层，**不是** `tokens` 里）：

| 字段 | 作用 |
|---|---|
| `preferDark` | 该主题偏好的明暗模式，**选中主题时一并应用**（不填 = 亮色）。主题包含明暗，所以选「暗夜」直接进暗色、选「清爽」回亮色 |
| `sideTheme` | 设成 `'theme-light'` 可做**浅色侧边栏**（「清爽」就是）。侧边栏令牌会自动转写到 `--sidebar-light-*` 那一族，边框和二级菜单底色按侧边栏色推导 |
| `dark`（在 `tokens` 块里） | 暗色模式下的令牌覆盖，未列出的键沿用 `light` |

> 主题预设**必须**区分明暗两套值（`light` / `dark`），不能只定一套 ——
> 同一个语义在两种模式下取值本来就不同（如侧边栏亮色 `#1a1f2e`、暗色 `#141414`），
> 只定一套会在切暗色时把默认值覆盖掉。
>
> 默认主题 `default-blue` 的取值**严格等于改造前的实际值**，改它会影响所有老用户的默认观感。

## 令牌怎么生效：内联 CSS 变量 + 三层回退

`applyTheme(preset, isDark, primary?)` 把令牌写成 `document.documentElement` 的
**内联 CSS 变量**。内联声明的优先级高于任何样式表规则，所以能稳定压过
`html.dark` 那一大块带 `!important` 的覆盖，**不需要自己再加 `!important`**。

未声明的令牌按这个顺序逐层回退：

```
内联样式（主题引擎写入）      ← 最高
   ↓ 未设置的令牌回退到
html.dark（暗色默认值）
   ↓ 再回退到
:root / SCSS 里 var() 的字面量回退值
```

**改样式时遵守一条规则：硬编码颜色一律写成 `var(--token, 当前值)`。**
这样令牌没被设置时外观与改造前完全一致——重构是零视觉回归的。

## 三条硬约束

### 1. 浅色侧边栏在暗色模式下强制回到 `theme-dark`

见 `syncSideTheme`。深底配浅侧边栏不成体系，且框架在 `html.dark` 里对 `.theme-light`
有一组 `!important` 覆盖，硬来会打架。

### 2. `syncSideTheme` 必须**无条件计算**

预设没声明 `sideTheme` 就回到 `theme-dark`。**不能**写成「没声明就不动」——
那样从「清爽」切到别的主题时 `theme-light` 会残留，出现错配。

### 3. `pageBg` 在暗色模式下不沿用亮色值

这是 `resolveTokens` 里**唯一的例外**。

`pageBg` 会写成 `--el-bg-color`，而 Element Plus 在 `html.dark` 里同时把
`--el-text-color-primary` 设成 `#ffffff`。一旦亮色的近白 `pageBg` 漏进暗色模式，
就会覆盖掉 `#141414`，变成**大面积白底白字**。设置抽屉、`el-tooltip` 首当其冲——
EP 的暗色 tooltip 是 `background: --el-text-color-primary` + `color: --el-bg-color`，
两个都变白就完全看不见。

所以**新加主题时 `dark` 块必须给 `pageBg`**。忘了也不会白屏（引擎会置空让它回退到
`html.dark` 的 `#141414`），但那套主题的暗色观感会变中性灰，失去色调倾向。

## 持久化：主题改动自动落盘

`setDark()` 内部调 `persistThemeSetting()`，只把 `themeId` / `customPrimary` /
`sideTheme` / `isDark` 四个字段**合并**进已存配置。不用点「保存配置」，
刷新也不会丢。

## 加一套新主题

1. 在 `src/config/themes.ts` 的预设数组里加一个对象
2. **`light` 和 `dark` 两套值都要给**，`dark` 块**必须包含 `pageBg`**（见硬约束 3）
3. 想让它默认进暗色 → 顶层加 `preferDark: true`
4. 想要浅色侧边栏 → 顶层加 `sideTheme: 'theme-light'`
5. 改了样式就跑像素回归（见 `docs/基建/像素回归测试.md`），默认主题必须 0 差异

## 设计取舍

### 为什么 `setDark()` 不用 `persistSetting()` 整体覆盖

`persistSetting()` 会把用户在布局设置里改过、但**还没点「保存配置」**的项
（navType、tagsView 等）也一并固化进存储，属于意外副作用。
「保存配置」按钮仍负责整体保存，主题切换不该越权。

### 为什么主题令牌写成内联样式而不是加 class

框架在 `html.dark` 里对一批 Element Plus 变量用了 `!important` 覆盖。
再叠一层带 `!important` 的样式表规则会变成打补丁，且优先级靠书写顺序决定、很脆。
内联变量的优先级天然高于任何样式表规则，是一次性的解法。

## ⚠️ 坑

### `el-menu` 的 TinyColor 陷阱 —— 传 CSS 变量字符串会变全黑

Element Plus 内部用 `new TinyColor(props.backgroundColor).shade(20)` 算悬停色。
传 `'var(--sidebar-bg)'` 这类 **CSS 变量字符串**会解析失败、**产出 `rgb(0,0,0)`**。

所以 `Sidebar/index.vue` 上**不要**给 `el-menu` 传 `:background-color` /
`:text-color` / `:active-text-color`，配色一律走 CSS 变量（`--el-menu-bg-color` 等）。

### scoped 样式对子组件内部元素无效 —— 是**静默**失效

`.el-menu-item` / `.el-sub-menu__title` 不是组件根，拿不到父组件的 `data-v` 属性
（实测 `hasScopeAttr` 均为 false）。给它们写 `color: v-bind(...)` 是**静默失效**的，
别被「看起来写了」骗到。菜单项的实际颜色由全局的 `sidebar.scss` 决定。

### `variables.module.scss` 的 `:export` 是**构建期常量**

JS 里 `import variables from '...module.scss'` 拿到的是编译后的死值，
运行时**不会**随主题变化。需要跟随主题的取值必须改用 CSS 变量字符串。

另：`.module.scss` 后缀**不能改名**，否则 `:export` 和 `@use` 都会断。

### `--current-color*` 必须在根元素上

原先绑在 layout 的 `.app-wrapper` 上，而 `el-dialog` / `el-drawer` / `el-message`
都 teleport 到 `body`，登录页也不在 layout 内——这些地方**统统取不到**。
现已由 `applyTheme` 写到 `documentElement`。**不要再往回改。**

### `Settings/index.vue` 的 navType watcher 不要「修」

```js
watch(() => navType, (val) => { if (val.value == 1) ... })
```

看起来像忘了解包（`val.value` 应为 `val`），但 getter 返回的是 **ref 对象本身**，
`val.value` 恰好是对的。实测点击「顶部菜单」后 `navType=3` 且 `sidebarOpened=false` /
`hideSidebar` 类正确加上，功能正常。

**按「bug」改成 `val` 反而会把导航模式切换改坏。**
