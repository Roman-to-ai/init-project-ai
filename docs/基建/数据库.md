# 数据库

库名 `@@DB_NAME@@`，root 密码 `@@DB_PASSWORD@@`，容器 `@@PROJECT_SLUG@@-mysql`，
宿主端口 `@@MYSQL_PORT@@`（容器内仍是 3306）。

## ⚠️ 库名带横线，SQL 里要加反引号

```sql
select * from `@@DB_NAME@@`.sys_menu;   -- ✅
select * from ry-vue.sys_menu;         -- ❌ 语法错误
```

写脚本时同理 —— 这也是 `scripts/doc-scan.mjs` 里每条 SQL 都写
`` `@@DB_NAME@@`. `` 的原因。

## 初始化

```bash
docker exec -i @@PROJECT_SLUG@@-mysql mysql -uroot -p@@DB_PASSWORD@@ \
    --default-character-set=utf8mb4 @@DB_NAME@@ < 脚本.sql
```

> **脚本不含建库语句**，需先建库。

## 两个生成器扩展列

本项目对框架的 `gen_table_column` 加了两列，**重新导入表会丢**：

| 列 | 作用 | 文档 |
|---|---|---|
| `is_common` | 查询条件常用/非常用（默认显示还是折叠） | `docs/生成器/查询条件常用非常用.md` |
| `validation_rule` | 校验规则 JSON（前后端唯一来源） | `docs/生成器/校验规则.md` |

> ⚠️ **`删除 + 导入表` 产生的是全新列配置，这两列全空。**
> 要保留已有配置请用**「同步数据库」**。

## 同步数据库（`synchDb`）—— 与手配列属性会互相覆盖

改了表结构后要把变更刷进生成器配置，正确做法是走生成器的**同步数据库**：

```
GET /tool/gen/synchDb/<表名>
```

> ⚠️ **生成器读的是 `gen_table_column.column_comment`，不是数据库表的列注释。**
> 只改表注释、重新导入建表 SQL，**生成的页面不会有任何变化**。
> （踩过：改了 `seq_no` 的注释想消掉与模板自带行号列的撞名，结果没生效。）

⚠️ **但 `synchDb` 会重置列的 `is_insert` / `is_edit` / `is_list`。**
它只对 isQuery 列保留 `is_common`（那是本项目给 `synchDb` 加的保留逻辑），
审计字段这类属性**会被打回默认值**，于是删除标志/创建者又回到表单里。

所以顺序不能反：

1. 先 `synchDb` 同步表结构
2. **再回头逐个重设列属性**（尤其审计字段的 `is_insert`/`is_edit`/`is_list`）

> 一句话记法：**`synchDb` 与「手配列属性」是一对会互相覆盖的操作。**
> 同步完必须回头检查列属性。


## ⚠️ 坑

### MySQL 8.4 的认证方式

JDBC URL **必须**带 `useSSL=false&allowPublicKeyRetrieval=true`，
否则 `caching_sha2_password` 连不上。

### 排查连接问题先确认端口

本项目用 `@@MYSQL_PORT@@` / `@@REDIS_PORT@@`（错开标准端口）。
报错只会说「连接被拒」，不会告诉你是谁占的。见 `docs/基建/环境与启动.md`。
