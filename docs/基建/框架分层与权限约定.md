# 框架分层与权限约定

> **改代码前先理解框架的分层，别自己发明模式。**
> 新增模块的完整操作步骤见 `.claude/skills/new-module/SKILL.md`；本篇讲**约定和为什么**。

## 后端分层

```
@@MAVEN_ARTIFACT_PREFIX@@-admin      Controller（HTTP 入口，@PreAuthorize 在这层）
   ↓
业务模块 / @@MAVEN_ARTIFACT_PREFIX@@-system   Service 接口
   ↓
ServiceImpl                          业务逻辑
   ↓
Mapper 接口                          ← Java 接口
   ↓
resources/mapper/**/*Mapper.xml      ← SQL 在这
```

**改一处通常要顺着这条链全改。** 加一个字段，六个文件都要动。

### 业务代码放 `@@MAVEN_ARTIFACT_PREFIX@@-biz`，不要散在 `@@MAVEN_ARTIFACT_PREFIX@@-system`

`@@MAVEN_ARTIFACT_PREFIX@@-system` 是框架的**框架模块**（`Sys*` 那一堆）。
把它当业务目录用有两个后果：

1. 业务代码和框架代码混在一起，将来升级框架要逐个分辨
2. 早期图省事放进去，后期想搬出来成本很高（包名、Mapper 命名空间、前端路径都要跟着动）

`@@MAVEN_ARTIFACT_PREFIX@@-biz` 已预置好，且 `generator.yml` 的 `packageName`
默认就指向它，**生成器里什么都不用改**。

> 以下三处**都不用改**，因为 `@@APP_CLASS@@` 在 `@@JAVA_PACKAGE_ROOT@@` 包下：
> 组件扫描（`@SpringBootApplication` 天然覆盖）、
> `@MapperScan("@@JAVA_PACKAGE_ROOT@@.**.mapper")`（通配符）、
> `typeAliasesPackage: @@JAVA_PACKAGE_ROOT@@.**.domain`（通配符）。

## 权限：两处必须逐字对上

```java
@PreAuthorize("@ss.hasPermi('biz:demoProduct:list')")
```

这个权限串必须跟 **`sys_menu` 表里的 `perms` 字段逐字一致**，
否则**前端菜单/按钮不显示，或点了 403**。

- 后端：Controller 每个方法一个 `@PreAuthorize`
- 数据库：`sys_menu` 里一条 `C` 菜单（`perms` 是 `...:list`）+ 若干 `F` 按钮
- 前端：`v-hasPermi="['biz:demoProduct:add']"` 控制按钮显隐

### ⚠️ 生成的菜单 SQL 不含角色授权

它只插 `sys_menu`，**不插 `sys_role_menu`**。`admin` 不受影响（框架对超级管理员
直接返回全部菜单），但**其他角色看不到新菜单**，要自己补：

```sql
insert into sys_role_menu values ('<roleId>', '<menuId>');
```

### ⚠️ 权限改动后必须**重新登录**

菜单和权限是**登录时缓存进 Redis** 的。不重登，改了也看不到。

## 接口返回

统一用 `AjaxResult` / `TableDataInfo`，**别直接返回裸对象**。

例外：树表模块的 `GET /list` 返回 `AjaxResult` 且**不调 `startPage()`**——
树没法分页。见 `docs/业务/演示产品分类.md`。

### 字段的线上形状：多值 → 数组，布尔 → `true`/`false`

**线格式按语义给，不按库表形状给**：

- 多值列（`checkbox` / 多选 `select`、`treeselect` / 图片 / 附件）→ **JSON 数组**；库里仍是逗号串
- `switch` → **`true`/`false`**；库里是 `char(1)` 的 `'1'`/`'0'`（老表 `tinyint(1)` 的 `1`/`0` 也认）。
  ⚠️ **查询区例外**：那里是「是/否」下拉、发 `'1'`/`'0'` —— 开关表达不了「不筛」，见 `docs/生成器/模板增强清单.md`
- 查询条件里的多值列 → **重复参数**（`?tags=1&tags=2`），不是 `tags[0]=`

转换由 `@@MAVEN_ARTIFACT_PREFIX@@-common` 的 `@MultiValue` / `@FlagValue` 两个注解在 Jackson
边界上做，**手写实体也能直接用**。完整契约、归一化表与上线顺序（**后端先行**）见
`docs/生成器/模板增强清单.md`。

> 收益：字段仍是 `String`（或 `Integer`），所以 `FieldRule` 校验、`@Excel` 导出、`find_in_set`
> 查询、Mapper 与数据库**全都不用动** —— 零 DDL、零数据迁移。

## 跨切面能力放哪

像「文件存哪儿」这类**跟具体业务无关、又可能换实现**的能力，本项目的落法是：

- **接口 + 默认实现** 放 `@@MAVEN_ARTIFACT_PREFIX@@-common`（无条件加载）
- **可选实现** 放独立模块（如 `@@MAVEN_ARTIFACT_PREFIX@@-storage-minio`），用 `@ConditionalOnProperty` 装配
- 不需要那个能力的项目，把 `@@MAVEN_ARTIFACT_PREFIX@@-admin/pom.xml` 里对应的
  `<dependency>` 删掉即可，其余一行不用动

> ⚠️ **条件注解要严格互补**：同一路径被两个提供者同时注册时，
> `@RequestMapping` 会**静默**赢过 resource handler，不报错、只是行为悄悄变了。
> 现成例子见 `docs/基建/文件存储.md`。

## 前端

| 约定 | 位置 |
|---|---|
| 请求封装 | `src/api/<module>/<business>.ts` |
| 页面 | `src/views/<module>/<business>/index.vue` |
| 类型定义 | `src/types/api/<module>/<business>.ts` |
| 权限指令 | `v-hasPermi` |

### ⚠️ 类型 barrel 必须手工合并

`src/types/api/index.ts` 是**统一导出文件**。生成器吐的是 `index-bak.ts`，
意思是「给你参考，自己合并进去」。要把新模块那行加进 `index.ts`：

```ts
// biz 模块
export * from "./biz/workOrder";
```

**漏了这步，TS 类型不会被导出，页面里 import 类型会报错。**

> 页面内部是**直连文件** import（`@/types/api/biz/demoProduct`），不走 barrel；
> barrel 是给其它地方用的统一出口。

## 优先走生成器，不要手写 CRUD

**手写必漏**菜单权限、字典、分页这些配套设施。生成器入口在
`@@MAVEN_ARTIFACT_PREFIX@@-generator` 模块，界面是**系统工具 → 代码生成**。

> 生成模板只有一套（Vue3 + Element Plus + TypeScript），**没有「挑前端类型」这回事** ——
> 上游那几套别的模板已经删掉了，见 `docs/生成器/模板增强清单.md`。

## ⚠️ 坑

### 顶级 `menu_type='C'` 菜单会多出一层无名包装

挂在顶级（`parent_id=0`）的业务菜单，框架的 `getRouters` 会为它生成一个
`name=None, path='/'` 的 Layout 包装层，实际 URL 是 `/demoOrder`。

功能正常，但真实项目更推荐**先建一个「业务管理」目录（`menu_type='M'`），
再把业务菜单挂在它下面** —— 层次清楚，也避免这层无名包装。

> 演示模块就是挂在顶级的，可以直接对照看。
