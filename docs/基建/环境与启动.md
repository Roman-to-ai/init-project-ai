# 环境与启动

> 日常三条命令。**启动/重启整个项目请用 `/start-project` skill**，它会连带验证全链路。

## 启动

```bash
# 1. 中间件（首次已初始化过，日常只需这条）
#    会起 4 个：mysql / redis / minio / minio-init。MinIO 是可选的 ——
#    后端 file.storage.type=local（默认）时它只是个闲置容器，不需要可整段删掉。
docker compose -f deploy/docker-compose.yml up -d

# 2. 后端 —— 改代码后需要重新打包
mvn -f backend/pom.xml clean install -DskipTests
java -jar backend/@@MAVEN_ARTIFACT_PREFIX@@-admin/target/@@MAVEN_ARTIFACT_PREFIX@@-admin.jar

# 3. 前端
pnpm -C frontend dev      # http://localhost，端口 80
```

访问 <http://localhost>，默认账号 `admin` / `admin123`。

> ⚠️ **改后端代码必须重新 `mvn install` 再重启 jar**，直接重启 jar 不会生效
> （除非用 IDE 的 devtools 热部署）。
>
> 同理，**改了 `vm/` 下的生成器模板也必须重新 `mvn install`** —— 模板是打在 jar 里的资源。

## 端口

| 服务 | 端口 | 配置在哪 |
|---|---|---|
| 前端 Vite | 80 | `frontend/vite.config.ts` 的 `server.port` |
| 后端 | 8080 | `backend/@@MAVEN_ARTIFACT_PREFIX@@-admin/src/main/resources/application.yml` 的 `server.port` |
| MySQL | 3307 | `deploy/docker-compose.yml`，容器内仍是 3306 |
| Redis | 6380 | 同上，容器内仍是 6379 |
| MinIO（可选） | `@@MINIO_PORT@@` | S3 API，容器内仍是 9000 |
| MinIO 控制台 | `@@MINIO_CONSOLE_PORT@@` | 容器内仍是 9001 |

> ⚠️ **别为了「统一」把 3307 / 6380 改回 3306 / 6379。**
> 开发机上往往同时跑着别的项目、占着标准端口。本项目刻意错开，
> 而且**报错信息不会告诉你是谁占的**——只会表现为「连接被拒」或
> 更糟的「连上了但连到别人的库」。MySQL 与 Redis 都只绑 `127.0.0.1`。

排查占用：

```bash
netstat -ano | grep LISTENING | grep ':<端口>\s'
```

## ⚠️ 坑

### Windows 停前端会残留进程

`pnpm dev` 的父进程被杀后，node 子进程仍占着 80 端口，表现为「重启后还是旧代码」
或「端口被占」。

而且 **Git Bash 会把 `taskkill /PID` 的 `/PID` 转成路径**，所以 `taskkill` 用不了：

```bash
powershell -NoProfile -Command "Stop-Process -Id <pid> -Force"
```

### 后端控制台中文乱码

Windows 控制台代码页问题，**不影响功能**（接口返回的中文正常）。
需要的话启动时加 `-Dfile.encoding=UTF-8`。

### MinIO 的 endpoint 别写 `localhost`

compose 把端口只绑在 IPv4 的 `127.0.0.1` 上，而 Windows 上 `localhost` 常先解析到
`::1`（IPv6）。症状是 `Connection refused`，且**看不出是 IPv6 的锅**。
`application.yml` 里已写死 `127.0.0.1`，别改。

### `sortablejs` 是上游遗漏的依赖

上游两个分支的 `package.json` 都**没写它**，但有 3 个组件 import 了。
已在 `frontend/package.json` 手工补 `1.15.7`。

**重新拉取上游代码后需要再补一次。** 类型声明不需要额外装，`src/types/global.d.ts` 里已有。
