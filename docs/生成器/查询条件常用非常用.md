# 查询条件的「常用 / 非常用」

> 生成的 CRUD 页面把顶部搜索条件分成两组：**常用的直接显示**，
> **非常用的默认折叠**，点「展开查看更多」才出现。

## 机制

| 环节 | 实现 |
|---|---|
| 存储 | `gen_table_column.is_common`（`char(1)`，`'1'` = 常用） |
| 模板 | 非常用项的 `el-form-item` 带 `v-show="expandQuery"` |
| 交互 | `toggleExpandQuery()` 控制展开/收起 |

> **默认值是「全部算常用」** —— 向后兼容，不配置时与旧版产物一致。

## AI 生成页面时的规划约定

**这些页面由 AI 规划，不由人工在生成器页面逐列点选。** 导入表后 AI 直接改 `is_common`：

```sql
-- 先看有哪些查询条件
SELECT column_name, column_comment, is_query, is_common, sort
FROM gen_table_column c JOIN gen_table t ON t.table_id = c.table_id
WHERE t.table_name = '你的表名' AND c.is_query = '1' ORDER BY c.sort;

-- 把次要条件收起来
UPDATE gen_table_column c JOIN gen_table t ON t.table_id = c.table_id
SET c.is_common = '0'
WHERE t.table_name = '你的表名' AND c.column_name IN ('plan_start', 'remark');
```

### 判断原则

按**业务重要性**分，不是按字段类型：

| 归入「常用」（默认显示） | 归入「非常用」（折叠） |
|---|---|
| 单据号、编码、名称 —— 一进页面就想按它找记录的 | 日期/时间区间（尤其 BETWEEN） |
| 状态、类型等枚举筛选 | 备注、描述等长文本 |
| 外键/关联对象的选择（所属车间、负责人等） | 金额、数量的区间筛选 |
| 用户日常高频使用的维度 | 审计字段、低频查询维度 |

> **目标是默认显示的条件恰好占满一行（约 3 个）。**

## ⚠️ 坑

### `RightToolbar` 的搜索区折叠有竞态

`animateSearch()` 把 `setTimeout(clear, 260)` 调度在**双层 `requestAnimationFrame` 之外**，
偶尔 `clear()` 不执行，`.` 内联 `max-height` 会**永久残留在 `el-form` 上**。

- 普通页面内容高度不变，所以**看不出来**
- 但页面里若有「展开查看更多」这类**会改变表单高度**的交互，新行就会被截断、点了没反应

生成的页面已用 `toggleExpandQuery()` 主动清理兜底。

> 要根治得改 `components/RightToolbar/index.vue` —— 那是**共享组件，回归面大**，
> 所以选择了在生成物里兜底而不是改组件。

### 改了模板必须重新打包

`vm/` 下的模板是**打在 jar 里的资源**，光改 `src/main/resources/vm/` 下的文件不会生效：

```bash
mvn -f backend/pom.xml clean install -DskipTests
# 再重启后端
```

> 生成器走 classpath 加载模板 —— 这条对**所有**模板改动都成立。
