# 生成器模板增强清单

> 本项目对代码生成器的 `vm/` 模板做了一批增强。

## 只有一套模板

生成器只认 `vm/vue/v3ts/`（Vue3 + Element Plus + TypeScript），所以**没有「选前端类型」这回事**。
「前端类型」的下拉、`gen_table.tpl_web_type` 列、后端那条参数链都已去掉 ——
存量库跑 `backend/sql/upgrade_20260914_drop_gen_table_tpl_web_type.sql`。

## 增强清单

| 增强 | 说明 |
|---|---|
| **17 种控件** | 清单见 `docs/生成器/字段类型.md` §1，各自可用的规则键见 `docs/生成器/校验规则.md` §1。上游只有 `datetime`，且它渲染成纯日期选择器 |
| **label 宽度自适应** | 上游硬编码 `68px`（查询区）/ `100px`（表单区），6 汉字标签会被拆成两行且**溢出表单被裁掉**。改为 `label-width="auto"` |

| **操作列固定右侧** | `fixed="right"`。列多必然横向滚动，不固定的话「修改/删除」一滚就出视野 |

| **富文本改「查看」按钮 + 弹窗** | 在单元格里直接渲染会撑高行且几乎不可读 |
| **跨字段校验** | `gtField` / `ltField` / `eqField` / `neField` |
| **表单/查询区兜底分支** | 未匹配的 `htmlType` 退化成普通文本框，**不再静默丢字段**。见下方「坑」 |
| **选择类三种选项来源** | `select`/`radio`/`checkbox` 的选项可来自**字典 / 写死代码 / 接口**，优先级依次递减。见 `docs/生成器/校验规则.md` §2。顺带清掉了两处不可达的 `&& $dictType` 死分支 |
| **多值传数组、布尔传 `true/false`** | 多值列（`checkbox` / 多选 `select`、`treeselect` / 图片 / 附件）线上是 JSON 数组，`switch` 线上是布尔；**存储形状不变**。见下方「多值字段与布尔值的传输约定」 |
| **关联字段的冗余显示列** | 关联字段旁边另存一份名称，列表 / 查询 / 导出直接吃它（不再是裸 ID）。前端提交时写、后端保存时用 SQL 子查询重算（权威）。见 `docs/生成器/表与关联.md` |
| **多对多走辅助表** | 配 `junctionTable` 四件套，生成物带：表单里的多选、先删后插中间表、按中间表重算显示列、删主记录时清关联。见 `docs/生成器/表与关联.md` §4 |
| **逻辑删除（可选开关）** | 扩展功能里勾「逻辑删除」：删按钮生成 `update … set del_flag='2'`（照框架 `SysUserMapper` 的范式：**`<delete>` 标签里包 update**，接口签名不变）、列表与详情自动带 `del_flag='0'`，且 `del_flag` **不再出现在 insert/update 里**（前端就改不动它了）。没勾的表保持物理删除 —— **默认行为零变化** |
| **下拉可搜 + 关联字段的表格选择器** | 查询区的下拉都带 `filterable`（可输关键字过滤）；`treeselect` 在**查询区与表单区**改用**表格选择器**：弹窗 + 关键字搜索 + 表格（能看多列，列由规则的 `pickerColumns` 指定）+ 树形目标走树形表格。见 `docs/生成器/表与关联.md` §2 |
| **三个表单都有「清空」** | 搜索区是「重置」（框架的叫法）；新增/编辑弹窗是第三个按钮「清空」。弹窗那条：清空**不关弹窗**（关弹窗是「取消」），字段多时先弹一次确认，**编辑态下保留主键**（清完点确定仍是更新这条，不会静默变成新增）。**文本字段写空串而不是 null** —— 否则点确定时老值会被「只写非 null 字段」的 update 静默保留（界面上看着清了、库里没清）；数字/日期类没法这么办（只吃 null，而 null 会被跳过），仍是保留原值 |
| **多值列列表宽度** | 多值列（`checkbox` / 多选）在列表里要并排显示多个标签，按标签字数估的 `min-width` 底 100px 放不下两个（两个两字标签约 96px + 单元格 padding 就换行了）—— 放宽到 150。见下方「坑」 |
| **附件列「查看 + 下载」** | `fileUpload` 列表列不再是裸文本，改成 `FileList` 组件（全局注册在 `main.ts`）：有附件显示「查看」→ 弹窗列附件（去掉上传时的 `_序列号` 后缀）→ 每个附件「下载」。下载走 `/common/download/resource`，用 axios 带 token 拉 blob 再 `saveAs`（`window.open` 导航不带 Authorization 会 401） |

> 长文本的 tooltip popper 会 teleport 到 `body`，scoped 样式够不到 ——
> 所以**宽度/换行控制写在 `inline style` 上**，不是 scoped CSS。
>
> 富文本用 `v-html` 渲染，**依赖后端 `HTMLFilter` 在入库时过滤**。

## 单表 / 树表 / 主子表**共用一个列表页模板**

`vm/vue/v3ts/` 下只有两个前端模板：

- `index.vue.vm` —— 列表页。**单表、树表、主子表都走它**，差异用 `#if($table.tree)` 表达
- `view.vue.vm` —— 详情页（`gen_view` 开启时才生成）

`VelocityUtils.getTemplateList()` 因此就只有一行 `templates.add("vm/vue/v3ts/index.vue.vm")`，
既不按 `tplCategory` 也不按 `tplWebType` 分支。

**为什么要合并**：合并前是「改一处必须记得改另一处」，而**漏了不报错**。本项目为此踩过三次
（`date`/`time` 漏树表、`is_common` 漏树表，以及树表丢了 `$column.list` 判断与
`@selection-change`）。合并后「只改了一套」这种失误**在结构上不可能再发生**。

代价是**合并本身也会丢东西** —— 所以下面单独记了一段。

查某个 `htmlType` 有没有分支（只需查一个文件）：

```bash
grep -o 'htmlType == "[a-zA-Z]*"' \
  backend/@@MAVEN_ARTIFACT_PREFIX@@-generator/src/main/resources/vm/vue/v3ts/index.vue.vm | sort -u
```

> 改这块之前，先确认 `vm/vue/v3ts/index-tree.vue.vm` **不存在**了。
> 如果它还在（比如 `target/classes/` 下的构建残留），说明你看到的不是最新的 jar。

## 多值字段与布尔值的传输约定

**线格式按语义给，存储形状不变** —— 转换收在 Jackson 边界上（两个字段级注解），
所以 `FieldRule` 校验、`@Excel` 导出、`find_in_set` 查询、Mapper、数据库**全都不用动**。

| | 线上（JSON） | 库里 |
|---|---|---|
| 多值列：`checkbox` / 多选 `select`、`treeselect` / `imageUpload` / `fileUpload` | `["1","2"]` | `varchar` 逗号串 `'1,2'` |
| 布尔列：`switch` | `true` / `false` | `char(1)` 的 `'1'`/`'0'`，或 `tinyint(1)` 的 `1`/`0` |

### 归一化表（排查问题时按这个对）

```
多值 · 请求   ["1","2"] → "1,2"    [] → ""（清空）   "1,2"（老前端）→ "1,2"   null → null
多值 · 响应   "1,2" → ["1","2"]    null / "" → []                       逐段 trim、丢空
布尔 · 请求   true → "1"  false → "0"   "1"/"0"/"true"/"false"/1/0 → 归一   null → null
布尔 · 响应   "1"/"true" → true    "0"/"false" → false                     null → null
```

> **`[]` 归一成 `""` 而不是 `null` 是刻意的**：Mapper 的 `<if test="tags != null">` 还得能看见
> 「清空」这个动作，归成 null 会让清空在 UPDATE 时**被静默丢弃**。
> `required` 照样拦得住 —— 空串是空白串。

### 两个注解（在 `@@MAVEN_ARTIFACT_PREFIX@@-common`）

| 注解 | 位置 | 要点 |
|---|---|---|
| `@MultiValue` | `common/annotation` | 数组 ↔ 逗号串。出参形状与存储形状不一致，差异收在这里 |
| `@FlagValue` | 同上 | 布尔 ↔ `'1'/'0'`（或 `1/0`）。**字段类型仍随库列走**（String 或 Integer），靠 `ContextualDeserializer` 问出目标类型再回对应形状 —— 写死成 String 就会在 Integer 列上炸 |

转换器在 `common/config/serializer/`，形态照抄既有的 `@Sensitive`（`@JacksonAnnotationsInside` 合成注解）。
`@MultiValue` 上必须带 `@JsonSerialize(nullsUsing = …)` —— 字段为 null 时 Jackson 不走 `serialize`，
漏了就出 `"tags": null`，前端 `el-checkbox-group` 会告警。

### 生成期怎么挂（判据收口在 `GenTableColumn`）

两个**派生判据**（不落库、与「加一个列属性要改 6 处」那份清单无关）：

- `isMultiValue()` —— `checkbox` / `imageUpload` / `fileUpload` / 规则里 `multiple` 为真
- `isMultiSelectQuery()` —— 上者**且有选项来源**（字典 / 写死 / 接口）：查询区会出多选的那个子集

| 模板 | 用它做什么 |
|---|---|
| `domain.java.vm`、`sub-domain.java.vm` | 挂注解。**多值列再判一次 `javaType == "String"`** —— 转换器是给 String 写的，把 checkbox 配在 int 列上属畸形配置，宁可不挂（挂了会在序列化时抛类型转换异常） |
| `index.vue.vm` | 提交不再 `join`、回显不再 `split`、`reset()` 给 `[]`（多值）/ `false`（开关）、查询区初值用 `isMultiSelectQuery()` 决定 `[]` 还是 `undefined` |
| `type.ts.vm` | 类型按**线上形状**给：多值 `string[]`、布尔 `boolean` |
| `mapper.xml.vm` | 多值列的查询条件用 `<foreach>` 拆开逐个 `find_in_set`；开关的查询区是「是/否」下拉，用普通等值即可 |

> ⚠️ `type.ts.vm` 里**实体接口与 QueryParams 同名不同形是刻意的**：实体是线上形状（数组），
> 而查询区的多值列未必出多选（图片/附件退化成单值文本框）—— QueryParams 用
> `isMultiSelectQuery()` 单独判。**这两处必须用同一个判据**，各写一份就会对不上（vue-tsc 报 TS2352）。

### 查询方向：GET 的退化形式

多选查询条件发的是**重复参数**（`?tags=1&tags=2`，见 `frontend/src/utils/common.ts` 的 `tansParams`），
不再是 `tags[0]=`。Spring 的 `ArrayToStringConverter` 把重复参数合成逗号串，落到实体的 `String tags` 上，
Mapper 再按逗号拆开逐个 `find_in_set` 用 `or` 连 —— 所以**查询语义是「包含任一值」，不是「全包含」**。

- 开关的**查询区是「是/否」下拉**（发 `'1'`/`'0'`，可清空），**不是 `el-switch`** —— 理由见「坑」里那条
- 因此开关的 Mapper 条件就是普通等值 `=`，**没有额外翻译**（`char(1)` 与 `tinyint(1)` 两种存法都吃）
- **导出仍是 GET**、条件照旧走 URL（没改，见下面的「没做的」）

### ⚠️ 上线顺序：后端先行

入站侧同时接受数组与逗号串，所以**后端先上**则老前端照常发逗号串；
**前端先上**则新数组打到老后端 → 400。

## ⚠️ 坑

### 合并丢过两处树表代码（已修，但改这块时要知道）

把旧的 `index-tree.vue.vm` 并进 `index.vue.vm` 时，**公共脚本区保留的是单表那套写法**，
两处树表专有代码没跟过来。两处的表现都是**不报错、页面不崩**，只是功能不对：

| 丢的代码 | 症状 |
|---|---|
| `getList()` 里的 `proxy.handleTree(response.data, ...)` | 树表后端返回 `AjaxResult`（全量数组在 `data` 里，**没有 `rows`/`total`**），走了单表的 `response.rows` → `list.value = undefined`，**表格整片空白** |
| `handleUpdate()` 里的 `getTreeselect()` | 没先点过「新增」就直接点「修改」，父节点下拉**是空的** |

两处现在都在 `index.vue.vm` 里用 `#if($table.tree)` 补回了。**这类「公共函数被单表版覆盖」
的丢失，只看模板文本看不出来** —— 只有对着产物、或真跑一次生成才发现。

核对办法：拿一份**合并前生成的树表页面**（现成的：
`frontend/src/views/biz/demoCategory/index.vue`）当基准，逐项对树表专有代码。

> 对比两个模板（或模板 vs 产物）时，用**行集合 diff**，别用逐行 diff ——
> 后者会被缩进和注释措辞的差异淹没：
>
> ```bash
> comm -23 <(sort -u 旧模板) <(sort -u 新模板)   # 「旧有新无」= 候选丢失，逐条过一遍
> ```

### 字段静默消失（三种成因，排查「某个筛选条件没生成」先看这里）

模板是 `#if / #elseif` 链，**不匹配任何分支时什么都不渲染** ——
不报错，而是 `el-form-item` 整个不存在。三种成因：

1. **`select` / `radio` 类型 + 空字典**（上游 bug）。分支条件是
   `"" != $dictType` / `$dictType`，`dictType` 为空串时**全为假**。
   框架不会从列注释自动推导 `dictType`，必须在生成器里手工选。
2. **列名含 `status` 的字段**：`GenUtils` 会把它自动设为 `radio`，若没配字典就命中上一条。
3. **配了模板不认识的 `htmlType`**：本轮踩过两次 —— 给 `produce_date` 配
   `htmlType="date"`（上游没有 `date` 类型），以及给树表的列配 `date`/`time`。

> **已修**：表单区和查询区现在都补了兜底分支，未匹配的 `htmlType` 退化成普通文本框。
> 但**旧的 vm 模板（`vue/`、`vue/v3/`）没补** —— 本项目不用它们。

### Velocity 的三个坑

**1. `0` 是假值。**

判空不能写真值判断 —— `#if($column.ruleMin)` 在 `min=0` 时为假，
配置被静默吞掉（生成出来的 `el-input-number` 少了 `:min="0"`）。

正确写法是**安静引用**：

```velocity
#if("$!column.ruleMin" != "")   ## null 渲染成空串再比
```

**2. HTML 注释里的指令也会被解析。**

在 `<!-- -->` 里写「井号 + `if`」之类，Velocity 照样当指令解析，模板**直接解析失败**
（报 `Encountered "#else"` 或 `<EOF>`）。

写「不要用某个指令」这类注释时，**别把指令本身写出来**。

**3. `$field.method(...)` 会被执行，而不是原样输出。**

想让产物里出现 `tags.split(',')` 这种**字面量**时，写成 `$javaField.split(',')` 会被 Velocity
**当方法调用执行**，产物变成 `[tags]`（数组的字符串化）—— 不报错，只是生成的
`<foreach collection="[tags]">` 永远取不到集合，**查询条件静默失效**。

要输出字面量就用**花括号形式**：`${javaField}.split(',')` —— 引用在 `}` 处收尾，后面全是纯文本。

> 同源的既有小坑没动：`$javaField.trim() != ''` 里的 `.trim()` 也一直被吃掉
> （产物是 `tags != ''`），白名单式判空少了 trim。
> 它对**所有列**生效、影响面超出本次改动，所以留着没改 —— 但别再照着写。
> **改模板后务必真跑一次生成，别只看模板文本。**

### 查询条件里的开关不能用 `el-switch`

`el-switch` 只有两个状态、**表达不了「不筛」**。它的值一旦既不是 `active-value` 也不是
`inactive-value`（比如查询条件的初值 `undefined`），Element Plus 会**自作主张把 inactive 值写回去**，
**并且 emit `change`** —— 于是用户完全没碰筛选，列表就已经被永久加上「等于否」：

```
GET /biz/demoProduct/list?pageNum=1&pageSize=10&isRecommend=0   ← 谁也没点过那个开关
```

单向绑定（`:model-value` + 只监听 `change`）**挡不住** —— 那个 `change` 正是它自己发的。

所以生成器把**查询区**的开关做成「是/否」下拉（`clearable`，清空即不筛，值发 `'1'`/`'0'`），
**表单区**才用 `el-switch`（那里值一定是布尔，不存在「未设置」）。

> 这条是**真跑一次生成 + 打开页面才发现的** —— 只看模板文本、甚至只跑 curl 都看不出来：
> 后端一切正常，是前端多送了一个参数。

### 树表的「树名列」必须排在第一列

`el-table` 的树形缩进**固定作用在第一列**，生成器改不了。而 `$columns` 是按
`gen_table_column.sort` 排的，**默认就是建表时的物理列序** —— 所以只要树名列前面
还有别的 `is_list` 列（如 `parent_id`、`ancestors`），缩进就会跑到那上面去，
看起来像「缩进挂在一个无意义的列上」。

修法：在生成器界面把树名列拖到最前，或直接改 `gen_table_column.sort`。

> 生成器其实**算了**树名列序号（`VelocityUtils.getExpandColumn` → `$expandColumn`），
> 但三套树表模板（v3ts 合并后的那份，加 `vue/`、`vue/v3/` 各一份）**都没用它**，
> 而是硬编码「第一个列表列」—— v3ts 里写作 `#if($table.tree && ${foreach.index} == 1)`。
> 那个硬编码恰好是 EP 需要的（「第一个列表列用朴素渲染」），
> 所以**问题不在模板，在列顺序**。

### 多值标签在列表里会换行错位（看起来像重叠）

`DictTag` 组件原来靠 `.el-tag + .el-tag { margin-left: 10px }` 撑标签间距。标签**并排**时没问题；
但列窄时标签会**换行**，`margin-left` 落在新行首，导致第二行标签错位、和上一行标签紧贴，
看起来像重叠/对不齐（实测：两个两字标签各 44px，第二个的 left 只比第一个大 5px，而不是 44+10）。

两层修法（缺一不可）：
1. `DictTag` 根 `div` 改成 `inline-flex + flex-wrap: wrap + gap: 4px 8px + max-width: 100%`，
   去掉 margin-left hack —— 换行后各标签仍对齐；`inline-flex` 保留父级 `text-align` 的居中。
2. 模板给多值列更宽的 `min-width`（100 → 150），让两个标签能并排放下，不用换行。

### 关联/字典字段在列表里显示原始值（0/1、id）

两个坑叠加，典型症状是「标签名称」这类**多对多辅助表的冗余显示列**在列表里显示成 `0`：

1. `DictTag` 组件的未匹配分支用了 Vue2 的 filter 语法 `{{ unmatchArray | handleArray }}`。
   Vue3 把 `|` 当**按位或**，`数组 | 函数` 算成 `0` —— 于是任何「值匹配不上选项」的 dict-tag 都显示 `0`。
   已改成 `{{ handleArray(unmatchArray) }}`。

2. 列表列渲染里 `ruleOptionsApi` 分支排在 `input/textarea` 之前，而**辅助表的冗余显示列**
   （`tag_names` 这类，本身就是存好的名称串，`isJunction()` 为真）也带 `optionsApi`，
   于是被 dict-tag 误渲染：拿「名称」去比「id」永远匹配不上，又落到上面的 `0`。
   已在 `ruleOptionsApi` 分支加 `&& !$column.junction`，让冗余显示列走普通文本渲染。

## 给生成器加一个新的列属性

以 `is_common` 为例，要改 **6 处**，**漏一处是静默失效**：

| # | 位置 | 漏了的失败模式 |
|---|---|---|
| 1 | `gen_table_column` DDL | 列不存在 |
| 2 | `GenTableColumn.java` 字段 + 四件套 | — （**必须有无参 `isCommon()` 布尔方法**，Velocity 的 `$column.common` 靠它） |
| 3 | `GenTableColumnMapper.xml`：resultMap / selectVo / insert / update **四处** | 漏 resultMap → 永远 null；漏 insert → 导入不落库；漏 update → 保存无效 |
| 4 | `GenTableMapper.xml`：**resultMap + 它的 3 处内联列清单** | 该字段为 null，`synchDb()` 的保留逻辑**静默失效** |
| 5 | `GenUtils.initColumnField()` | 默认值缺失 |
| 6 | `GenTableServiceImpl.synchDb()` | 同步数据库时**不保留**该配置 |

> ⚠️ **第 4 处最容易漏** —— `GenTableMapper.xml` **不走**共享的
> `selectGenTableColumnVo`，要单独维护 3 处内联列清单。
